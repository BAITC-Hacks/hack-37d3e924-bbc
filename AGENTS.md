# Работа с проектом

- Основное приложение находится в `frontend/`, `backend/`, `ai/`; отдельного прототипа нет.
- Перед изменением интеграции прочитайте `ARCHITECTURE.md`, `docs/API_CONTRACT.md` и `docs/ML_CONTRACT.md`.
- Формат входа/результата задаётся `contracts/`. Не меняйте поля незаметно для потребителей.
- Профиль `brev` запускает собственный API и модели на Linux-сервере NVIDIA Brev. Он не вызывает NVIDIA Build API.
- Не устанавливайте зависимости Apple MLX в профиль Brev. Не считайте наличие Brev доказательством наличия GPU.
- Пользовательские записи и модельные веса не включайте в Docker-образ. Не коммитьте `.env`, ключи и новые записи.
- Сохраняйте лицензии и атрибуцию моделей при очистке репозитория.
- Исходный результат AI неизменяем; исправления сохраняются с проверкой версии и ссылок на реплики.
- Явно отмечайте fixture; ошибку реальной модели нельзя заменять синтетическим результатом.
- Изменения должны сохранять исходный язык, глобальные таймкоды и проверяемые источники поручений.
- Проверки: `python -m pytest backend/tests ai/tests scripts/tests -q`, `npm test --prefix frontend`, `npm run build --prefix frontend`, `docker compose config --quiet`, `git diff --check`.
- Полный тест контейнера и настоящее распознавание на Brev отдельно отмечайте как непроверенные, если нет доступа к Docker/VM/моделям.
- Сохраняйте незакоммиченные изменения пользователя. Независимые подзадачи можно поручать субагентам с непересекающимися файлами.
