# Архитектура приложения

React/TypeScript → FastAPI → SQLite/локальные аудиофайлы → отдельный worker → `ai.pipeline.run_pipeline` → проверка контракта → исходный результат → исправленная версия → DOCX.

API раздаёт собранный `frontend/dist`, принимает файлы, проверяет метаданные и декодирование. Тяжёлые модели загружает только отдельный worker. Задание захватывается короткой транзакцией SQLite; обработка идёт вне транзакции. Блокировка worker привязана к базе, AI имеет дополнительную блокировку своей рабочей папки.

`contracts/` — источник формата входа и результата. HTTP-оболочка — `docs/API_CONTRACT.md`. Изменений схем для этой интеграции не требуется; статус согласования BASELINE сохраняется.

Машинный результат неизменяем. PUT review проверяет весь собранный результат, ссылки и календарные даты; `expected_revision` сравнивается в одной транзакции с записью. Экспорт получает одну сохранённую версию. Несохранённые правки не экспортируются из интерфейса.

Профили: mac (локальные TorchScript CTC, ONNX-диаризация, MLX), cuda (настроенные владельцем локальные GPU-модели), fixture (явно синтетическая проверка приложения). Ошибка real никогда не переключает режим.

Один запуск: `scripts/manage.py run` поднимает API и worker отдельными группами процессов и останавливает обе при выходе. Хранение по умолчанию `.local/app`, API на loopback. Docker, внешняя аутентификация и распределённые worker не заявлены готовыми.

Старый `prototypes/meeting-mvp` остаётся самостоятельным приложением; его исправления покрывают сохранение анализа, историю версий, источники ручных поручений и сверку повторов.

## Ограничения проверки

Код backend/frontend поступил при слиянии `59df640`; вывод старого ревью об отсутствии этих каталогов больше не описывает текущую версию. Наличие кода и синтетические регрессии не доказывают сквозную работу исходных моделей на целевой машине.

Оригинальные модели сохранены. Полный MLX-профиль требует поддержанной среды Apple Silicon и исходных весов. Два приложения используют независимые хранилища и блокировки; запускать оба конвейера на одном ограниченном GPU одновременно без общей координации нельзя.

Аудио и текст совещаний не отправляются внешним API. Зависимости и веса подготавливаются отдельно; затем полный сценарий проверяется с запрещённым исходящим доступом. Фикстура явно маркируется и не включается при сбое настоящей модели. Статус общего контракта остаётся BASELINE до фактического согласования команды.
