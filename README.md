# Хаттама — протокол совещания из аудио

Русская, казахская и смешанная речь → расшифровка с говорящими → поручения с источниками → проверка человеком → сохранённый DOCX. Аудио и текст обрабатываются локальными моделями; облачного fallback нет.

**Веса уже включены в репозиторий: [models/asr](models/asr), [models/diarization](models/diarization), [models/llm](models/llm).** После `git clone` или `git pull` выполните `python3 scripts/prepare_repo_models.py` (на Windows: `py scripts/prepare_repo_models.py`). Команда соберёт большие файлы из частей и проверит SHA-256 без сети. Git LFS и GitHub CLI для этого способа не нужны. [Инструкция для команды](models/README.md).

## Запуск приложения

Основной интерфейс: React/TypeScript, FastAPI, SQLite и отдельный worker, который вызывает `ai.pipeline.run_pipeline`. API не загружает модели. Исходный результат сохраняется отдельно от исправлений; одновременные правки защищены номером версии.

Для Mac/Linux-профилей используйте **Python 3.12**; Windows-профиль с исходными моделями проверен на **Python 3.14.6**. Нужны **Node.js 22.13+** и npm. Команды выполняются из корня репозитория. `make up` работает в переднем плане: **Ctrl+C останавливает API и worker вместе**. Локальный адрес — **http://127.0.0.1:8000**. Сервер не публикуется во внешнюю сеть.

### Apple Silicon: настоящие локальные модели

```bash
cp .env.example .env
make setup PROFILE=mac
make up PROFILE=mac
```

По умолчанию запуск использует `models/` этого репозитория и сам собирает веса при необходимости. Комплект: `asr/model.pt`, `asr/tokens.lst`, `diarization/segmentation.onnx`, `diarization/embedding.onnx` и полный каталог `llm/` с MLX Qwen. Другой каталог можно явно указать через `MODELS=/absolute/path/to/models`.

Проверка ранее скачанных файлов без сети:

```bash
MEETING_MODEL_DIR=/absolute/path/to/models .venv/bin/python prototypes/meeting-mvp/download_models.py --verify-only
```

Все части весов хранятся непосредственно в Git. Комплект занимает около 3.08 ГБ; с историей Git и собранными копиями подготовьте 12 ГБ свободного места. Резервная копия также доступна в [GitHub Release models-mac-v1](https://github.com/BAITC-Hacks/hack-37d3e924-bbc/releases/tag/models-mac-v1). [Инструкция, отдельные компоненты и лицензии](models/README.md).

Можно также использовать имеющийся каталог или перенести веса с подготовленной машины: [подключение и копирование](prototypes/meeting-mvp/README.md#уже-скачанные-веса-и-ошибка-401403). На другом компьютере локальный путь будет другим. GitHub хранит веса, а для обработки приложение нужно запустить на совместимой машине.

### Проверка интерфейса без тяжёлых моделей

```bash
make setup PROFILE=fixture
make up PROFILE=fixture
```

Загрузите корректный WAV/MP3/M4A/FLAC и укажите дату записи. В этом режиме аудио проверяется на декодируемость, затем возвращается **явно помеченный синтетический результат**. Он не подтверждает качество распознавания и не включается при ошибке реального AI. Режим фиксируется для каждой записи и виден в интерфейсе и DOCX.

### Windows / PowerShell: интерфейс на синтетическом результате

`make` и `chmod` не нужны. При первой установке:

```powershell
python scripts/manage.py setup --profile fixture
python scripts/manage.py run --profile fixture
```

Скрипт использует `.venv\Scripts\python.exe` или уже подготовленное окружение `prototypes\meeting-mvp\.venv\Scripts\python.exe`. Путь можно задать через `--python`. Для текущего компьютера с установленным окружением:

```powershell
.\prototypes\meeting-mvp\.venv\Scripts\python.exe scripts/manage.py run --profile fixture
```

Откройте **http://127.0.0.1:8000**. Терминал оставьте открытым; Ctrl+C завершает API и worker. Модели в профиле `fixture` не запускаются и не заменяются. Исходный MLX-профиль требует Apple Silicon.

### Windows: оригинальные модели через PyTorch

Windows-профиль использует те же mixed-STT, Sherpa ONNX и Qwen3-4B-Instruct-2507-4bit из закреплённого комплекта. Новый адаптер читает исходный MLX-файл частями; веса не заменяются и не переквантуются. Подробности, ограничения памяти и проверенные результаты — [ai/WINDOWS.md](ai/WINDOWS.md).

```powershell
python scripts/manage.py setup --profile windows
# Один раз подготовьте оригинальный комплект (GitHub CLI с доступом к репозиторию):
python scripts/download_models.py --directory .local/models
# Для NVIDIA: устанавливается в то же окружение, где работает worker.
.\prototypes\meeting-mvp\.venv\Scripts\python.exe -m pip install torch==2.14.0+cu130 --index-url https://download.pytorch.org/whl/cu130
.\prototypes\meeting-mvp\.venv\Scripts\python.exe scripts/manage.py doctor --profile windows --device cuda
.\start-windows.cmd
```

Если установка создала корневое `.venv`, используйте `.venv\Scripts\python.exe` вместо пути прототипа. CUDA-команда рассчитана на совместимый NVIDIA-драйвер; CPU-профиль доступен через `start-windows.cmd -Device cpu`. Ярлык выбирает доступный PyTorch CUDA при запуске, иначе CPU, и печатает выбранное устройство. Сбой обработки не переключает модель, устройство или режим на фикстуру.

По умолчанию нужен каталог `.local/models`; другой путь задаётся `-Models "C:\path\to\models"`. Перед запуском проверяются комплект файлов, зависимости и поддержка выбранного устройства. `doctor` дополнительно пересчитывает SHA-256. Предыдущий тестовый сервер на порту 8000 сначала остановите через Ctrl+C.

### Linux с NVIDIA GPU

```bash
make setup PROFILE=cuda
# Подготовьте локальные веса и AI_* настройки в .env по ai/README.md.
make up PROFILE=cuda
```

Нужны совместимые CUDA/cuDNN, драйвер и FFmpeg для выбранных библиотек. Точные настройки, модели, лицензии и замеры: [AI README](ai/README.md), [модели](ai/MODELS.md), [доказательства](ai/EVIDENCE.md). Этот профиль не считается проверенным на GPU только потому, что работают Mac и тестовый режим.

Docker Compose пока не поставляется: общие команды запускают приложение напрямую. Старые команды Makefile, ссылавшиеся на отсутствующий Compose, удалены.

## Как проверить протокол

1. Загрузите запись, укажите её реальную дату/время, часовой пояс и известных участников. Например: 23 сентября 2026, 10:00, `Asia/Almaty`. Интерфейс сам добавляет UTC-смещение; дата не подставляется автоматически.
2. Дождитесь завершения очереди. Отображаются реальные этапы, без придуманного процента.
3. Сопоставьте голоса с участниками, исправьте саммари, исполнителей и сроки. Для ручного поручения выберите исходные реплики.
4. Нажмите «Сохранить правки». Пустой источник, невозможная дата или неизвестный исполнитель не сохраняются. Неизвестный срок/исполнитель требуют проверки.
5. Повторно откройте сохранённую версию и скачайте DOCX. Экспорт заблокирован в UI при несохранённых правках. Исходный результат ИИ доступен отдельно и не перезаписывается.

Ошибочную обработку можно повторить. Обрабатываемую запись нельзя удалить. После аварийного завершения worker незавершённые записи становятся `failed`; нужен явный retry. Второй worker для той же базы не запускается.

## Данные и настройка

`scripts/manage.py` читает `.env` как `KEY=value`, не выполняя shell-код. Переменные процесса имеют приоритет. Не коммитьте `.env`.

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `DATA_DIR` | `.local/app` | Записи и состояние приложения |
| `DATABASE_PATH` | `DATA_DIR/meetings.sqlite3` | База SQLite |
| `MAX_UPLOAD_BYTES` | `104857600` | Предел загрузки, 100 МиБ |
| `BACKEND_PORT` | `8000` | Порт локального API и интерфейса |
| `MEETING_MODEL_DIR` | не задан | Каталог весов для профиля mac |
| `AI_STATE_DIR` | `DATA_DIR/ai-private` | Приватные промежуточные данные AI |

Профиль запуска задаёт `PIPELINE_MODE` и `AI_MODE` согласованно. API и worker должны использовать одну базу и одинаковые серверные пути. Путь ноутбука не работает на удалённом сервере.

Для уже подготовленных отдельных Python-окружений:

```bash
python3.12 scripts/manage.py run --profile mac --models /path/to/models \
  --python /path/to/api-venv/bin/python --worker-python /path/to/ai-venv/bin/python
```

## Ограничения

- Это черновик протокола: точность имён, казахской/смешанной речи, диаризации и поручений требует проверки человеком. Синтетические тесты не заменяют метрики на настоящих совещаниях.
- Сверка поручений между частями выполняется локально и ограничена по числу сравнений. Подтверждённые уточнения сохраняют исходные цитаты; неоднозначные случаи остаются для ручной проверки. Семантическая безошибочность не гарантируется.
- Сервис рассчитан на локальный доступ. Для общего сервера ещё нужны согласованные аутентификация, резервное копирование и защита сети. Не открывайте текущий порт в Интернет.
- Offline-флаги и блокировка сокетов AI дополняют, но не заменяют сетевую изоляцию закрытого контура.

Старый самостоятельный [Streamlit-прототип](prototypes/meeting-mvp/README.md) сохранён: `make prototype` после его отдельной установки. Новый интерфейс использует общий контракт и хранение backend; базы двух приложений не смешиваются.
