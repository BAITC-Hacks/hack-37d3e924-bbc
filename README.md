# Хаттама

Локальный протокол совещания: загрузка аудио → расшифровка с говорящими → поручения и саммари → проверка человеком → DOCX.

Приложение предназначено для русской, казахской и смешанной речи. Модели работают на машине, где запущен worker. Аудио, транскрипты и результаты не отправляются в облачные API. Ошибка модели завершает задание ошибкой; автоматического перехода на облако или тестовую фикстуру нет.

## Быстрый запуск на Windows

Проверенная машина: Windows, Python **3.14.6**, NVIDIA RTX 3050 Laptop **4 ГБ**, RAM **16 ГБ**. Нужны Git, Python 3.14, Node.js **22.13+** и npm. Для CUDA нужен совместимый NVIDIA-драйвер; проверена сборка PyTorch **2.14.0+cu130**. CPU доступен явно, но полный комплект на CPU не замерялся.

После клонирования перейдите в корень репозитория:

```powershell
.\setup-windows.cmd
.\start-windows.cmd
```

Откройте **http://127.0.0.1:8000/**. Терминал оставьте открытым. **Ctrl+C** останавливает API и worker. Повторная установка для каждого запуска не нужна. Скрипты используют корневую `.venv`.

Явный выбор устройства:

```powershell
.\setup-windows.cmd -Device cuda
.\start-windows.cmd -Device cuda
# Без совместимой NVIDIA GPU:
.\start-windows.cmd -Device cpu
```

`auto` выбирает CUDA при подготовленной поддержке NVIDIA, иначе CPU. Выбранное устройство печатается при запуске. После ошибки обработки оно не меняется автоматически.

## Веса и работа без сети

В `models/` находятся исходные файлы и части больших весов. Готовый комплект занимает около **3.08 ГБ**; клону, частям и собранным файлам требуется дополнительное место. Подготовка собирает части прямо в `models/` и проверяет размеры и SHA-256; модель не заменяется и не переквантуется.

```powershell
.\.venv\Scripts\python.exe scripts/prepare_repo_models.py
.\.venv\Scripts\python.exe scripts/manage.py doctor --profile windows --device cuda
```

По умолчанию подготовленный комплект находится в корневом `models/`. Сборка использует `models/repository-models.lock.json` и не обращается к сети. Можно подключить уже подготовленную папку:

```powershell
.\start-windows.cmd -Models "D:\meeting-models" -Device cuda
```

Если репозиторий получен без больших файлов, доступен отдельный загрузчик закреплённого [GitHub Release](https://github.com/BAITC-Hacks/hack-37d3e924-bbc/releases/tag/models-mac-v1). Нужен GitHub CLI и доступ к репозиторию:

```powershell
gh auth login
python scripts/download_models.py --directory models
python scripts/download_models.py --directory models --verify-only
```

Установка пакетов и доставка весов требуют сети. После подготовки основной сценарий использует локальные файлы; worker включает offline-флаги и запрет Python-сокетов. Проверка с физически отключённой сетью или сетевой изоляцией ОС остаётся отдельным приёмочным шагом. Лицензии и происхождение весов: [models/NOTICE.md](models/NOTICE.md).

## Основной сценарий

1. Создайте совещание: название, фактические дата/время, IANA-зона, известные участники и аудио WAV/MP3/M4A/FLAC. По умолчанию лимит загрузки — 100 МиБ.
2. Дождитесь обработки. Интерфейс показывает очередь и текущий этап, без выдуманных процентов.
3. Сопоставьте метки говорящих с людьми, проверьте саммари, исполнителей, сроки и исходные реплики поручений. Автор реплики не обязательно исполнитель.
4. Сохраните правки. Неизвестный исполнитель или срок остаются пустыми и требуют уточнения.
5. Повторно откройте совещание и скачайте DOCX. Экспорт использует сохранённую версию; исходный машинный результат хранится отдельно.

После перезапуска записи и правки сохраняются. Хранятся исходный результат и последняя редакция; полной истории редакций пока нет. Повторная обработка разрешена для задания с ошибкой. Удаление работающего задания заблокировано до завершения обработки.

## Структура проекта

```text
ai/              локальные модели, конвейер, валидация и метрики
backend/         FastAPI, SQLite, очередь, worker, DOCX
frontend/        React/TypeScript и компоненты проверки
contracts/       JSON Schema, HTTP-контракт и синтетические примеры
models/          исходные веса/части, манифесты и лицензии
scripts/         установка, запуск, подготовка моделей и проверки
data/            исходные материалы хакатона
.local/          БД, загруженные аудио и локальные отчёты; исключено из Git
.venv/           единое Python-окружение; исключено из Git
```

Устройство системы, контракты и ограничения: [ARCHITECTURE.md](ARCHITECTURE.md).

## Настройки

Необязательный `.env` создаётся из `.env.example`; секреты и новые пользовательские записи в Git не добавляются.

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `DATA_DIR` | `.local/app` | База, аудио и приватные временные файлы |
| `BACKEND_PORT` | `8000` | Локальный HTTP-порт |
| `MAX_UPLOAD_BYTES` | `104857600` | Максимальный размер аудио |
| `MEETING_MODEL_DIR` | `models` | Подготовленный комплект моделей |
| `AI_CONTEXT_TOKENS` | `2048` в Windows | Контекст LLM вместе с ответом |
| `AI_MAX_NEW_TOKENS` | `512` в Windows | Лимит ответа на один фрагмент |

Нельзя передавать worker путь к файлу на другом компьютере: загрузку сохраняет backend в доступное ему локальное хранилище. Одновременно обрабатывается одна запись.

## Проверки и воспроизводимость

```powershell
.\.venv\Scripts\python.exe scripts/manage.py verify
.\.venv\Scripts\python.exe scripts/check_data.py
```

`verify` запускает тесты AI, backend и инструментов, тесты frontend, TypeScript-проверку, production build и компиляцию Python. Тесты используют синтетические данные и не требуют загрузки больших моделей в память. `check_data.py` локально проверяет декодирование аудио и DOCX из `data/`, сохраняет только технический отчёт в `.local/data-smoke`; это не оценка качества ASR/LLM. `--diarize --models models` дополнительно запускает настоящую ONNX-диаризацию. Отчёт содержит метаданные и проверки, без текста документов; исходные файлы не изменяются. Код выхода: 0 — проверки пройдены, 1 — ошибка, 2 — запрошенная диаризация заблокирована отсутствующими весами.

Для знакомства с интерфейсом без моделей:

```powershell
python scripts/manage.py setup --profile fixture
.\.venv\Scripts\python.exe scripts/manage.py run --profile fixture
```

Режим явно подписан как тестовый в приложении и DOCX. Он не распознаёт загруженное аудио и не подтверждает качество моделей.

### Проверено на исходных моделях

23.09.2026 на Windows выполнена обработка специально синтезированного русского аудио с двумя голосами: **20.8 секунды записи за 197 секунд**, 6 реплик, 2 говорящих и 2 поручения. Пик выделенной памяти PyTorch на GPU — **2.443 GiB**, пик RSS процесса LLM — **2.849 GiB**. Счётчик PyTorch не включает все выделения ONNX и драйвера. [Технические метрики](ai/evidence/windows-original-models.json).

Проверены загрузка через HTTP, отдельный real-worker, правка в браузере, сохранение, неизменность исходного результата, DOCX с казахскими буквами и сохранность после перезапуска. В этом запуске модель пропустила относительный срок и ошиблась в связи фразы со сроком в саммари. Эти поля исправлены вручную. Проверка воспроизводимости запуска не равна оценке точности.

### Что ещё ограничивает качество

- Русская, казахская и смешанная речь поддерживаются выбранным ASR, но независимые WER/DER и полнота поручений для трёх языковых сценариев не измерены в текущей Windows-приёмке.
- Метки голоса не устанавливают личность; имена требуют ручного сопоставления.
- Сроки, поручения и саммари — черновик. Неоднозначные даты требуют проверки.
- Длинное аудио разбивается на окна, текст — по контексту; сквозная приёмка длинных записей ещё не проведена.
- Это локальное приложение без публичной авторизации и распределённой очереди. По умолчанию слушает только `127.0.0.1`.

### Приёмка и показ за 3–5 минут

Покажите проблему ручного протоколирования, загрузку короткой записи, этапы обработки, два голоса, поручение другому участнику, переход к источнику, исправление и DOCX. Объясните отдельный worker и локальные модели, приведите измеренные время/память и ограничения. Для языковой приёмки нужны три обезличенные записи — русская, казахская и смешанная — минимум по два голоса, с относительным сроком, отсутствующим сроком и репликой, которая не является поручением.

Развитие после обязательного сценария: проверенный набор языковых тестов, улучшение извлечения дат, ускорение локальной генерации и удобная история исправлений. Оценки качества и баллы жюри заранее не заявляются.

## Другие платформы

Apple Silicon использует те же исходные веса с MLX:

```bash
python3.12 scripts/manage.py setup --profile mac
.venv/bin/python scripts/prepare_repo_models.py
.venv/bin/python scripts/manage.py run --profile mac --models models
```

Профиль `cuda` для Linux оставлен для отдельной настройки `AI_*` и локальных библиотек. Его подготовительные зависимости закреплены, но он не считается проверенным лишь потому, что работает Windows-профиль. Docker-развёртывание не заявлено готовым.
