# Проверка ИИ-модуля — 23.09.2026

Это результаты локальных запусков, отдельно от серверных планов. Компьютер: Apple M2, 8 GB общей памяти, macOS, Python 3.12. NVIDIA не подключалась. Локальные исходные записи, транскрипты и ответы LLM в Git не включены. В `ai/evidence/` находятся только обезличенные технические метрики.

## Что проверено

- Общая синтетическая фикстура проходит схемы команды и проверки ссылок/дат.
- 45 автоматических тестов: неверные ссылки/даты, IANA-offset, порядок таймкодов, двойное владение голосом, явный fixture, отсутствие fallback, bounded context, устранение дублей на стыке ASR-окон, сохранение настоящих повторов, запрет сетевых сокетов worker, работа валидации при Python `-O`.
- Полный локальный конвейер на 40.452 s синтетического RU/KK-аудио: 30.834 s, 4 сегмента, 2 голоса, 3 поручения + саммари, контракт валиден. Число голосов заранее не навязывалось. Голоса macOS Aru/Milena, команды для воспроизведения — `ai.make_synthetic_demo`.
- Этапы этого запуска: декодирование 0.270 s; ASR 6.016 s; диаризация 5.305 s; извлечение/саммари 17.929 s. Пиковый RSS одного этапа около 1.53 GiB; отдельно пик выделений MLX около 2.61 GiB unified memory. Это разные счётчики, их нельзя называть CUDA VRAM или полным суммарным расходом памяти машины.
- Реальный локальный фрагмент предоставленного аудио, 45 s: полный pipeline завершился за 62.371 s, 6 сегментов, 2 метки говорящих, 0 поручений. Ноль задач здесь не доказывает полноту извлечения. Дата для smoke-теста взята из фикстуры, фактическая дата записи неизвестна; это не готовый протокол для исполнения.

## Сравнение ASR на одинаковых клипах

Модели загружались только с локального диска, decoding без внешнего API. Whisper: CTranslate2 int8, beam=5, язык auto на каждом окне, task=transcribe. CTC: оригинальный TorchScript checkpoint, greedy, без KenLM и дополнительного квантования. Один короткий русский TTS-клип (16 слов), один двухголосый смешанный TTS-клип (62 слова), первые три взятых тестовых клипа [FLEURS kk_kz](https://huggingface.co/datasets/google/fleurs) (57 слов суммарно). Это **smoke-набор**, не репрезентативный benchmark совещаний и не метрика полного FLEURS.

| Модель | RU TTS WER | Mixed TTS WER | KK 3 клипа, общий WER | Mixed ASR время |
|---|---:|---:|---:|---:|
| Alibi mixed-CTC | 6.25% | **8.06%** | 17.54% | 4.77 s |
| OpenAI large-v3-turbo | 12.50% | 51.61% | 24.56% | 44.39 s |
| Shyngys Kazakh Turbo | 12.50% | 43.55% | **14.04%** | 40.53 s |

WER учитывает слова, регистр/пунктуация нормализованы; числа цифрами и словами остаются разными. На одном KK-клипе Shyngys дал 0 ошибок, на двух других значительная часть расхождений связана с записью чисел. Времена включают загрузку ASR; фоновая подготовка весов могла влиять на Mac, поэтому это ориентиры, не изолированный speed benchmark. По этим данным нельзя судить о GPU-скорости или обобщать качество на все совещания.

Дополнительно: одна синтетическая фраза с переключением языка внутри предложения (10 слов, Aru) дала WER 30% у mixed-CTC, 30% у Shyngys и 50% у OpenAI Turbo. Поэтому 8.06% из таблицы не переносится на всё «шала-казахское»: таблица в основном проверяет смену языка между репликами. Метрики отдельного теста — `evidence/intrasentence-metrics.json`.

Начальный выбор для mixed-MVP: **Alibi mixed-CTC**. Причина — меньше ошибок на данном mixed-тесте при коротком локальном времени. Shyngys оставлен казахским кандидатом; его чисто казахский результат не является доказательством mixed-качества. Оба Whisper-профиля реализованы и запущены. Large-v3 без turbo не измерялся; переключения по предполагаемому языку или автоматического ансамбля нет.

## Выявленные ошибки и пределы результата

Локальная MLX Qwen3-4B — тестовая альтернатива. В синтетическом end-to-end тесте все три действия обнаружены, но пары «исполнитель/срок» совпали с ожидаемыми только у одного действия. ASR исказил имя; LLM также связала имя из соседнего поручения с задачей по бюджету и пропустила срок. Проверка наличия имени в исходной реплике не доказывает смысловую связь. Поэтому все задачи помечены needs_review, а неподтверждённые значения обнуляются. Эту конфигурацию нельзя выдавать за проверенную автоматическую постановку поручений без секретаря.

У 4B выявлена лишняя кавычка после целого JSON. Первый запуск завершился ошибкой, как и должен был. Теперь допускается только узкая синтаксическая нормализация такого суффикса после проверки целого объекта; она отражается в warnings. Другие ошибки допускают один локальный форматирующий повтор; невалидный итог приводит к failed.

Объединение длинного текста и глобальные таймкоды реализованы и имеют граничные тесты. Нагрузочного прогона 60/120 минут пока нет. DER и точность голосовой идентификации не измерены; синтетические интервалы включают паузы и не являются ручной разметкой DER. Система вообще не устанавливает личность по тембру.
