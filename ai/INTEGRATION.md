# Передача участнику приложения и тимлиду

Рабочая ветка: `codex/ai-pipeline`, основание `origin/fix/master-merge` (контракт BASELINE v1). Меняется только `ai/`; общие зависимости, схемы, README, backend, frontend и экспорт не изменены.

- Импорт `from ai.pipeline import run_pipeline`, синхронный вызов из отдельного worker-процесса. Вход/выход точно по `contracts/`. Проценты и новые поля не добавляются.
- Прогресс и безопасные `PipelineError(code, message)` соответствуют предложению `docs/ML_CONTRACT.md`.
- Обычный запуск: локальные веса обязательны. Ошибка → failed. Ни fixture, ни cloud не включаются после ошибки.
- Явная fixture-конфигурация принимает общий `ai/fixtures/input.json`; JSON копирует контрактную фикстуру без изменения смысла. Это режим для разработки, не подтверждение качества.
- AI-зависимости ставить в окружение worker из `ai/requirements-cuda.lock.txt` (Linux/Python 3.12). GPU runtime ещё не проверен. Если worker импортирует общие пакеты backend, финальное объединение зависимостей согласовать с тимлидом; этот PR их не меняет.
- Один серверный `AI_STATE_DIR` для всех worker-процессов; файловый lock запрещает вторую одновременную запись. Очередь, retry, восстановление после kill принадлежат приложению.
- Дата совещания обязательна: offset должен совпадать с timezone. Метки голосов не подтверждают имена. Участники могут иметь пустые `speaker_ids`.
- Передавайте известные имена участников заранее. Иначе исполнители остаются null даже при упоминании имени. Все задачи пока требуют проверки; даты без года и неоднозначные сроки не придумываются.
- Доступ к Brev пользователь отложил. Community-1 требует принятия HF-условий владельцем аккаунта. До GPU/закрытого контура нужно выполнить реальную проверку CUDA + 14B + Community-1 и сетевую изоляцию.

DOCX подтверждает исходные требования. В копии документов тимлида ещё указано «DOCX недоступен» — можно обновить статус владельцу этих файлов. Изменений контракту v1 для этой реализации не требуется.
