# Локальный ИИ-модуль совещаний

Область: только `ai/`. Модуль импортируется worker-процессом приложения; отдельного HTTP-сервера, UI, БД и экспорта здесь нет. Источник формата — `contracts/` команды. DOCX прочитан: обязательны RU, KK, смешанная речь, говорящие, поручения, саммари и экспорт на стороне приложения.

## Подключение к приложению

```python
from ai.pipeline import run_pipeline
from ai.errors import PipelineError

result = run_pipeline(input_data, on_progress=lambda event: print(event))
```

Синхронный вызов. `audio_path` — существующий локальный файл, доступный worker. Дата с UTC-offset должна соответствовать IANA-зоне на эту дату. Известные участники имеют `id`, `name`, `speaker_ids`; если голос ещё не сопоставлен, `speaker_ids=[]`. Модуль не угадывает соответствие голоса имени. Ответственный извлекается из содержания поручения и сопоставляется с известными участниками. Неизвестные исполнитель/срок остаются `null`. Все автоматически извлечённые поручения в этой версии имеют `needs_review=true`.

Прогресс: только `{"stage": "preparing_audio"}` и этапы из `docs/ML_CONTRACT.md`. В callback не передаётся содержимое записи. Ошибки — `PipelineError` с безопасными `code`, `message`; приложение также должно обрабатывать аварийное завершение процесса. Не публикуйте traceback. Ошибка модели никогда не включает облако или фикстуру.

Один вызов за раз: файловая блокировка `AI_STATE_DIR/inference.lock`. Все worker-процессы на сервере должны использовать один `AI_STATE_DIR`. Модели запускаются последовательными отдельными процессами; память освобождается после каждого этапа. Временные файлы находятся в приватном каталоге и удаляются при обычном завершении/исключении. После принудительного убийства родительского worker администратор должен удалить оставшиеся каталоги `meeting-*` после проверки отсутствия активных задач. Настройка жизненного цикла worker принадлежит приложению.

## Фикстура для параллельной разработки

```bash
python -m pip install -r ai/requirements-base.txt
AI_MODE=fixture python -m ai ai/fixtures/input.json --output /tmp/fixture-result.json
```

Принимается только точная общая фикстура из `contracts/examples/input.json`, скопированная без изменений в `ai/fixtures/`. Аудио не требуется. Результат явно содержит `TEST_FIXTURE`. В обычном режиме `AI_MODE=real` необходимы локальные веса. backend должен выставлять `mode=fixture` из собственной конфигурации и отображать тестовую маркировку.

## Подготовка CUDA-сервера

Проверенный код и локальные замеры не означают, что серверная связка уже проверена на GPU: доступ к NVIDIA/Brev отложен пользователем. `python -m ai.probe > hardware.json` собирает модели/число GPU, VRAM, RAM, диск, CUDA/driver и версии пакетов без чтения секретов. Фактические тарифы, баланс и доступность GPU проверяются в аккаунте Brev отдельно.

Предварительный первый эксперимент: одна карта с 24 GB и Qwen3-14B NF4, короткий контекст 8192, batch=1, последовательные этапы. Это гипотеза для проверки вместимости, не измеренный минимум. Если есть выгодная карта 40–48 GB, сравнить с BF16 без квантования; выбор 80 GB или нескольких GPU только после измерений и проверки цены. Балансы участников не объединяем. Обучения нет.

Из корня репозитория, Python 3.12, Linux x86_64:

```bash
python3.12 -m venv .venv-ai
. .venv-ai/bin/activate
python -m pip install -r ai/requirements-cuda.lock.txt
python -m pip check
python -m ai.probe > /data/hardware.json
```

Нужны системные FFmpeg shared libraries (например, пакет `ffmpeg` Ubuntu), а не только исполняемый файл imageio. Pyannote 4.x использует TorchCodec. В зафиксированной конфигурации Torch/TorchAudio 2.9.0 + TorchCodec 0.8.1. Для faster-whisper/CTranslate2 нужны CUDA 12 cuBLAS и cuDNN 9. Если библиотеки установлены через pip, добавьте их каталоги в `LD_LIBRARY_PATH` **до** запуска worker, как в официальной инструкции faster-whisper. Драйвер должен поддерживать выбранную CUDA. Этот документ не меняет общие зависимости или Docker команды — тимлид подключает отдельный AI worker environment.

## Веса: загрузка отдельно от обработки

Точные revision и лицензии перечислены в `ai/models.json`, официальные источники — в `ai/MODELS.md`. На подготовительном компьютере с интернетом:

```bash
python -m ai.prepare_models whisper-turbo --directory /models/whisper-turbo --convert
python -m ai.prepare_models kazakh-turbo --directory /models/kazakh-turbo --convert
python -m ai.prepare_models mixed-ctc --directory /models/mixed-ctc
python -m ai.prepare_models community1 --directory /models/community1
python -m ai.prepare_models qwen14b --directory /models/qwen14b
# Для сравнения более крупного Whisper:
python -m ai.prepare_models whisper-large-v3 --directory /models/whisper-large-v3 --convert
```

Не обязательно скачивать все кандидаты: для первого серверного эксперимента достаточно одного ASR + Community-1 + Qwen14B. `--convert` создаёт соседний каталог `*-ct2`; копирует tokenizer/preprocessor, чтобы inference не скачивал их. Для CPU-конверсии есть `--quantization int8`. Хеши файлов и revision сохраняются в `provenance.json`. В закрытый контур переносите полные каталоги с конфигурациями, токенизаторами и лицензиями.

Community-1 требует принятия условий доступа на Hugging Face и токена чтения для загрузки. Токен передайте через локальное окружение или HF credential store на этапе подготовки; не в код, git, аргументы CLI или чат. Принятие условий выполняет владелец аккаунта. Подписки pyannoteAI не нужны: `precision-2` и внешние API не используются.

## Настройка настоящего конвейера

```bash
export AI_MODE=real
export AI_ASR=mixed_ctc
export AI_ASR_PATH=/models/mixed-ctc
export AI_DIARIZER=community1
export AI_DIARIZATION_PATH=/models/community1
export AI_LLM=transformers
export AI_LLM_PATH=/models/qwen14b
export AI_DEVICE=cuda
export AI_COMPUTE_TYPE=float16
export AI_QUANTIZATION=nf4
export AI_STATE_DIR=/data/ai-private
export AI_METRICS_PATH=/data/last-ai-metrics.json
python -m ai /data/input.json --output /data/result.json
```

В примере выбран mixed-CTC по первому mixed-тесту. Для сравнения можно **явно** выбрать `AI_ASR=whisper` и путь `*-ct2`. Shyngys подключается через тот же Whisper-адаптер, меняется только локальный путь. `AI_LANGUAGE` не задан по умолчанию: Whisper определяет язык в каждом акустическом окне. Для сравнительного чисто казахского теста допустимо `AI_LANGUAGE=kk`; не навязывайте его смешанной речи без проверки. `AI_NUM_SPEAKERS` задаётся только при известном числе голосов; количество приглашённых участников не считается числом реально говорящих.

Локальный профиль Mac (Apple Silicon, macOS 14+): `ai/requirements-mac.lock.txt`, `AI_ASR=mixed_ctc`, `AI_DIARIZER=sherpa`, `AI_LLM=mlx`, `AI_DEVICE=cpu`. Требуются каталог CTC (`model.pt`, `tokens.lst`), каталог ONNX (`segmentation.onnx`, `embedding.onnx`), локальная MLX-модель. Проверенные происхождение и хеши альтернативных весов — `ai/mac-models.lock.json`. Подготовка: `AI_MAC_MODEL_DIR=/models/mac python -m ai.prepare_mac_models` (скачивание по закреплённым SHA256). Это явно выбираемая тестовая связка, не автоматическая замена Qwen14B/Community-1.

## Ограничения и приватность

- По умолчанию до 60 минут; `AI_MAX_SECONDS` — от 1 до 7200. Больше лимита — ошибка, не скрытая обрезка. Базовый лимит — ограничитель ресурсов, часовая запись ещё не проходила нагрузочный тест.
- Whisper: окна 24 s с контекстом по 2 s; CTC: 12 s с контекстом по 0.8 s. Таймкоды глобальные; слово принадлежит окну по середине интервала, совпадающие пересекающиеся слова удаляются. Реальные повторы «да да» сохраняются.
- Диаризация выполняется по полной ограниченной записи с одним глобальным кластерингом. Это сохраняет идентичность меток между ASR-окнами, но не является потоковой диаризацией. Перекрытие голосов отмечается предупреждением.
- LLM получает группы реплик по фактическому числу токенов, с перекрытием двух реплик. По умолчанию контекст 8192, выход 2048 (`AI_CONTEXT_TOKENS`, `AI_MAX_NEW_TOKENS`). Саммари объединяются иерархически. Точные повторы поручения автоматически объединяются только при общем источнике и известном одинаковом исполнителе.
- После извлечения похожие поручения одного известного исполнителя сопоставляются той же локальной моделью вместе с исходными репликами: максимум 64 сравнения, каждое в лимите контекста. Разные явные номера объектов/периодов не объединяются. Модель выбирает отношение между готовыми поручениями, не создаёт новые поля. Срок заменяется только при явном изменении в строго более позднем источнике: дословная цитата должна содержать новый срок, который независимо вычисляется правилами дат. Сохраняются старые и новые источники, `needs_review=true`.
- Неоднозначные повторы, разные/неизвестные исполнители, неразрешимые даты и сравнения сверх лимита сохраняются для ручной проверки; предупреждения сообщают о неподтверждённых повторах/изменениях. Это не гарантирует семантическую дедупликацию: изменение без повторного указания действия/исполнителя может не попасть в извлечение соседней части, а сильно разные формулировки — в кандидаты сопоставления. Лимит сравнений ограничивает дополнительные вызовы модели, но не гарантирует время обработки часовой записи. Новые проверки используют синтетические ответы модели; они подтверждают ограничения алгоритма, а не точность на живой речи.
- Относительные даты считаются от переданного `meeting_datetime` в `timezone`. Простые «завтра»/«ертең» и числовые календарные интервалы поддержаны. Рабочие дни, неоднозначные дни недели и даты без года остаются null: согласованной бизнес-политики для них нет.
- JSON проверяется, ссылки на несуществующие реплики отклоняются. Один форматирующий повторный запрос выполняется только той же локальной моделью. Известный дефект локальной 4B — одна лишняя конечная кавычка — удаляется только после проверки полного JSON-объекта и с явным warning. Это не семантическая гарантия правильности поручения.
- В inference включены HF offline и запрет телеметрии; дочерний Python-процесс блокирует сетевые сокеты. Аудиодекодер разрешает только локальные протоколы. Это защита на уровне приложения, не замена firewall/network namespace. Для приёмки закрытого контура запустите worker с запрещённым исходящим трафиком после подготовки весов (например, контейнер `--network none`). На сервере эта проверка пока не выполнена.
- Веса загружаются только отдельной командой `prepare_models`. Автоматических скачиваний, облачного inference и OpenAI-вызовов в pipeline нет. Запись и текст не попадают в progress, метрики или клиентскую ошибку.
- `AI_METRICS_PATH` содержит только длительности, выбранные адаптеры и память. RSS — отдельно от MLX unified memory; CUDA sampling — по PID через nvidia-smi. Torch peak не учитывает CTranslate2, поэтому есть отдельный sampled GPU peak. Неполученные показатели — null, а не выдуманный ноль.

## Проверки и сравнение моделей

```bash
python -m pip install pytest
python -m pytest ai/tests -q
# На Mac с голосами Aru и Milena: синтетическая запись двух голосов
python -m ai.make_synthetic_demo /data/synthetic-demo
# Приватный manifest: [{"id":"kk-1","audio_path":"/data/test.wav","reference":"..."}]
python -m ai.evaluate /data/manifest.json --output /data/asr-evaluation.json
```

`evaluate` измеряет только ASR: это не успешный результат полного pipeline. Содержимое гипотез сохраняется локально, такой файл не следует публиковать с реальными данными. WER/CER нормализуют регистр/пунктуацию, но не заменяют цифры словами. Для честного сравнения используйте одни и те же клипы, language/beam/quantization, отдельный процесс, фиксированные reference и ручную проверку поручений. Выбор модели и текущие ограничения — `ai/EVIDENCE.md`.

Проверка переносимости 23.09.2026: 50 тестов `ai/tests` проходят на Windows 11 / Python 3.14.6, включая межпроцессную блокировку, казахские CTC-токены при системной кодировке cp1251 и запуск `python -m ai.evaluate --help`. На Windows используется `msvcrt`, на Unix — `fcntl`; JSON и словарь токенов читаются и пишутся в UTF-8. Если системный `resource` недоступен, peak RSS равен `null`. Это проверка кода и синтетических фикстур, не подтверждение запуска CUDA/MLX-моделей на Windows. Полный inference проверяется отдельно в среде выбранного профиля.
