# Локальное приложение

Запускать из корня репозитория, после установки `backend/requirements.txt` и сборки `frontend/dist`:

```sh
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
python -m backend.worker
```

Это два отдельных процесса. API не загружает модели. Worker обрабатывает по одному заданию и вызывает `ai.pipeline.run_pipeline`. Для реального режима также установить зависимости и подготовить веса по `ai/README.md`. `/health` подтверждает работу HTTP, а не наличие моделей.

Оба процесса должны использовать одинаковые переменные окружения:

- `DATA_DIR` — каталог аудио и состояния, по умолчанию `.local/app`.
- `DATABASE_PATH` — SQLite, по умолчанию `$DATA_DIR/meetings.sqlite3`.
- `PIPELINE_MODE=real` — режим по умолчанию; `fixture` включается только явно.
- `MAX_UPLOAD_BYTES=104857600` — предел аудиофайла.

Режим сохраняется в каждом задании. При реальной обработке worker принудительно устанавливает `AI_MODE=real`; автоматического перехода на синтетический результат нет. В `fixture` приложение адаптирует общий синтетический пример под метаданные, но не распознаёт загруженный звук. В интерфейсе и DOCX результат отмечен как тестовый.

Загрузка проверяет размер потока и локальное декодирование WAV/MP3/M4A/FLAC до создания задания. Максимальная длительность декодирования сейчас — 3600 секунд, минимальная — 0.5 секунды. Источники-плейлисты запрещены. Клиент не выбирает серверный путь файла.

SQLite хранит исходный результат отдельно от исправлений. Сохранение требует актуальный `expected_revision`; проверка и увеличение версии происходят в одной транзакции. Экспорт читает одну последнюю сохранённую версию. Удаление и захват очереди также сериализуются транзакцией; удаление во время обработки возвращает 409, ошибка удаления файла — 500.

Worker удерживает файловую блокировку рядом с SQLite. Второй worker завершается, не трогая задания первого. После аварийного завершения следующий worker переводит оставшиеся `processing` в `failed`; повтор запускается пользователем. При SIGTERM/SIGINT worker останавливает свою группу дочерних процессов, прерывает текущий этап и освобождает блокировку; обработку можно повторить после восстановления. Прямой запуск из shell отделяет группу worker от вызывающего процесса. Для разовой обработки доступен `python -m backend.worker --once`. Рабочее хранилище должно быть на локальном диске одного сервера; сетевые SQLite/lock-файлы не поддерживаются.

Тесты (без моделей и облака):

```sh
python -m pip install -r backend/requirements-dev.txt
python -m pytest backend/tests -q
```

Проверки покрывают загрузку → отдельный worker → правку → повторное чтение после рестарта → DOCX, неизменяемый original, валидацию источников/дат/участников, конфликт версий, атомарный захват очереди, повтор/восстановление, блокировку второго worker и ошибки удаления. Синтетические проверки не являются измерением качества моделей.
