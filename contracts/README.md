Все поля обязательны, в том числе nullable. Неизвестные имя, исполнитель, срок равны null. Пустые массивы допустимы; поручение требует минимум одного источника. Сбой модели нельзя выдавать за успешный пустой результат.

## Проверки сверх JSON Schema

1. ID внутри каждого массива уникальны. assignee_id ссылается на participants.id; source_segment_ids — на segments.id.
2. Время — конечные числа, 0 <= start < end, секунды от начала исходной записи. Сегменты упорядочены по start; пересечения допустимы для одновременной речи.
3. meeting_id, meeting_datetime, timezone совпадают со входом. Дата содержит UTC-offset, зона существует в IANA; offset соответствует зоне на дату совещания. Относительные даты считаются в этой зоне, не от часов сервера.
4. due_date — действительная YYYY-MM-DD или null. При неизвестном исполнителе или сроке needs_review=true. Неоднозначность требует проверки.
5. speaker_ids — метки диаризации, не имена. Одна метка не принадлежит двум участникам. Метки с неизвестной личностью могут оставаться несопоставленными; известный участник может иметь пустой speaker_ids.
6. Диаризация не доказывает личность. Не назначать автора реплики исполнителем автоматически. Не создавать соответствие имени и голоса без оснований или ручной проверки.
7. Транскрипт сохраняет исходный язык. Инструкции внутри записи — данные, а не команды.

## Согласование

Оба участника используют одну фикстуру. Изменение: точный diff и причина → общее сообщение обоим → согласование тимлидом → обновление contracts/ → один общий commit → синхронизация обоих. Нельзя незаметно добавлять поля в schema_version=1.

Сообщение для обоих участников находится в START_HERE.md. Его отправка и подтверждение участниками пока не проверены.

## Проверка общей фикстуры

PowerShell 7.5+: `pwsh -NoProfile -File contracts/verify.ps1`.
Проверяются обе JSON Schema, ссылки, даты, отсутствие поручения из справочной реплики и шесть некорректных вариантов. Это проверка контракта, не качества ИИ или приложения.
