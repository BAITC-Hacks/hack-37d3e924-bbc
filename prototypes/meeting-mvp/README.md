# Хаттама — локальный протокол совещания

Промежуточный MVP: запись → транскрипт с говорящими → проверка секретарём → поручения и саммари → DOCX.

**Статус: рабочий прототип, качество извлечения поручений ещё настраивается.** Результат является черновиком: модель может пропустить поручение, перепутать исполнителя или срок. У каждого поручения есть исходные реплики для проверки. Нет облачного распознавания или внешнего LLM API.

## Что реализовано

- Загрузка MP3, WAV, M4A, OGG, FLAC, MP4: до 200 МБ и 30 минут.
- Локальное распознавание моделью для русского, казахского и смешанной речи.
- Автоматическая диаризация, приблизительные временные отметки, прослушивание записи.
- Ручное подтверждение имён говорящих и исправление транскрипта.
- Локальное извлечение поручений и саммари; исполнитель определяется по тексту, а не просто по говорящему.
- Неуказанные исполнитель и срок остаются пустыми. Календарная дата не выдумывается без даты совещания.
- Редактирование таблицы, сохранение и открытие локальных результатов.
- Экспорт DOCX, TXT и JSON.
- Отдельный режим готового текста и явно обозначенный синтетический пример.

## Быстрый запуск

Текущая реализация рассчитана на **macOS Apple Silicon**, Python 3.12. Проверена на MacBook Air M2, 8 ГБ, macOS 27.0. Зафиксированные версии MLX зависят от версии macOS; Linux/Windows этим установочным сценарием не поддерживаются.

```bash
cd prototypes/meeting-mvp
chmod +x setup.sh start.command
./setup.sh
./start.command
```

После запуска открыть **http://127.0.0.1:8501**.

На Windows нужен Python **3.12 или новее**. Используйте PowerShell или терминал VS Code:

```powershell
cd prototypes\meeting-mvp
.\setup.ps1
.\start.cmd
```

Если PowerShell запрещает запуск локального скрипта в текущем окне:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\start.cmd
```

`setup.ps1` не меняет системную Execution Policy и по умолчанию не скачивает веса моделей. Если нужен быстрый показ интерфейса, синтетический пример и локальное сохранение транскрипта, достаточно команд выше. Для попытки скачать исходные веса из `models.lock.json` выполните `.\setup.ps1 -DownloadModels`.

Ограничение Windows-режима: исходный LLM прототипа — `mlx-community/Qwen3-4B-Instruct-2507-4bit` через MLX. MLX не является native Windows backend, поэтому этот launcher запускает интерфейс и локальные функции без замены модели на другую. Полный сценарий поручений и саммари запускайте на поддержанной macOS Apple Silicon среде.

Первичная установка требует сети для Python-пакетов и примерно 3 ГБ весов. `download_models.py` скачивает фиксированные версии и проверяет SHA-256 из `models.lock.json`. Аудиозаписи на этапе установки не читаются. После установки модели загружаются с диска.

Если зависимости и модели уже установлены, повторно запускать `setup.sh` не нужно.

Переменные окружения, необязательные:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MEETING_MODEL_DIR` | `models/` рядом с приложением | Каталог весов |
| `MEETING_DATA_DIR` | `.local/` рядом с приложением | Локальные записи, результаты и журналы |

## Уже скачанные веса и ошибка 401/403

Повторная загрузка не нужна, если сохранился каталог `models`. Для прямого подключения
на машине участника, где запускался прототип:

```bash
export MEETING_MODEL_DIR="/Users/daryn/Documents/Codex/2026-09-23/x20/work/models"
python3 download_models.py --verify-only
./start.command
```

Этот путь проверен локально 23.09.2026; на другом компьютере или сервере нужно
указать свой путь после переноса файлов. Переменная должна быть задана в той же
оболочке, из которой запускается приложение. `--verify-only` проверяет SHA-256
всех файлов по `models.lock.json`, ничего не скачивает и обновляет локальный
receipt готовности только после успешной полной проверки.

Можно проверить или перенести отдельный компонент: добавьте `--component diarization`
(также доступны `asr` и `llm`; параметр можно повторять). В запись готовности входят
только файлы, действительно проверенные по размеру и SHA-256. Наличие весов LLM
не включает анализ, если среда MLX недоступна.

Для копирования готовых весов в стандартный каталог прототипа:

```bash
MEETING_MODEL_DIR="$PWD/models" python3 download_models.py --from-local /path/to/existing/models
```

`--from-local` копирует только файлы из манифеста, проверяет оригиналы и копии и
не обращается к сети. Если файл отсутствует или повреждён, команда завершается
ошибкой; уже корректные файлы не копируются повторно. Веса остаются вне Git.
При обычной загрузке ошибка 401/403 теперь подсказывает эти способы подключения.

Исходный ASR: `asr/model.pt` (756007202 байт) и `asr/tokens.lst` (266 байт).
Ожидаемые SHA-256:

```text
model.pt    92fe1791d7c93f385fc10a959dd216caa98c6a571df72f11d1605c6327393b88
tokens.lst  d6e8335d2268efc64e3e5e4dfaeadc749998248f126aa6a9f2a3190c317db4d1
```

`MEETING_MODEL_DIR` относится к этому прототипу. TorchScript ASR, ONNX-диаризация
и MLX Qwen имеют разные форматы; эти веса нельзя автоматически подставлять вместо
Whisper/CTranslate2, pyannote или GPU Qwen в `ai/`. Для нового worker используйте
конфигурацию его AI-модуля. Настройка этого каталога не меняет интерфейс
`ai.pipeline.run_pipeline` или JSON-контракты backend/frontend.

## Демонстрационный сценарий

1. Загрузить обезличенное аудио. Участники должны быть уведомлены о записи и транскрибации.
2. Указать дату совещания, если она известна. Не заменять её датой запуска приложения.
3. Нажать «Распознать запись» и дождаться обоих этапов.
4. Прослушать фрагменты, подтвердить имена, исправить имена собственные и числа в транскрипте.
5. Нажать «Сформировать поручения и саммари».
6. Сверить задания с исходными репликами, исправить исполнителей и сроки. Для добавленного вручную поручения выбрать «Исходные реплики». Перед сохранением и экспортом проверяются ссылки и календарные даты `YYYY-MM-DD`; цитаты восстанавливаются из выбранных реплик. Неизвестный срок можно оставить пустым.
7. Сохранить правки локально или скачать DOCX.

Для быстрой проверки интерфейса доступен синтетический текст. Это **не** демонстрация распознавания аудио или диаризации.

Сохранение транскрипта после редактирования протокола сохраняет также текущие поручения и саммари. Исходный машинный результат находится отдельно в поле `original`, правки его не перезаписывают. У старых сохранений без этого поля исходную версию восстановить нельзя. Для завершённых новых задач анализа сохраняются ссылка на локальное аудио и происхождение текста; тестовая маркировка переносится в JSON и DOCX. DOCX включает имена участников и при отключённом экспорте транскрипта.

## Архитектура

```text
Streamlit, локальный интерфейс и backend
  ├─ FFmpeg → моно 16 кГц
  ├─ Sherpa-ONNX → интервалы говорящих
  ├─ TorchScript ASR → слова и приблизительные отметки → реплики
  ├─ проверка секретарём
  ├─ Qwen через MLX → JSON → проверка ссылок, исполнителей и сроков
  └─ python-docx → DOCX; TXT / JSON
```

Тяжёлые этапы запускаются отдельными процессами, чтобы освобождать память. Межпроцессная блокировка предотвращает одновременную обработку нескольких совещаний. Модели ничего не исполняют из текста совещания; инструменты и действия им не предоставляются.

| Задача | Модель / реализация |
|---|---|
| ASR | `alibiserikbay/kazakh-russian-mixed-stt`, `asr/rukk`, greedy CTC |
| Диаризация | Sherpa-ONNX, pyannote segmentation 3.0 + 3D-Speaker ERes2Net |
| Поручения и саммари | `mlx-community/Qwen3-4B-Instruct-2507-4bit` |

Это самостоятельный прототип в `prototypes/meeting-mvp`. Он пока не реализует шаблонные REST/ML-контракты основного командного каркаса. Существующие `frontend/`, `backend/`, `ml/` и их контракты не изменены.

## Проверки

```bash
.venv/bin/python -m pytest tests -q
.venv/bin/python -m compileall -q .
```

Проверки автора исходного прототипа на macOS (история промежуточного коммита):

- 8 тестов проходят: даты без выдуманного года, исполнитель отличается от говорящего, отсутствие исходной реплики, защита цитат от переписывания, неизвестные поля, наложение голосов, длинный импорт текста, разбор JSON.
- Две русскоязычные записи длительностью около 4:34 и 3:26 обработаны локально. Диаризация + ASR заняли около 99 и 160 секунд соответственно в конкретных тестовых запусках. Это не обещание производительности на других машинах.
- Тест интерфейса Streamlit прошёл без исключений на начальном экране и на заполненном синтетическом результате; присутствуют три кнопки экспорта.
- Двухстраничный тест DOCX отрендерен и визуально проверен.
- Извлечение поручений на реальных записях ещё требует настройки. Есть ошибки имён, привязки к участникам и пропуски поручений. Надёжные WER/DER и полнота извлечения пока **не измерены**.
- Отдельная проверка казахского и смешанной речи продолжается. Поддержка языков в модели не равнозначна подтверждённой точности на совещаниях.

### Проверка Windows и файлов хакатона

Проверено на Windows 11, Python 3.14.6: установка `setup.ps1`, ответ `ok` от локального сервера, 48 тестов прототипа (включая остановку worker, блокировку, перенос моделей, восстановление анализа, старые сохранения без хеша, сохранность правок, буквальный вывод текста и проверку DOCX). Вместе с `ai/tests` — 98 тестов. Тесты используют синтетические данные и не подтверждают качество моделей. `pip check` не обнаружил конфликтов при подготовке среды. Зафиксированные Windows-зависимости находятся в `requirements.windows.lock.txt`.

Команды из каталога `prototypes/meeting-mvp`:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
# Только подготовка весов: сеть нужна, данные совещаний не читаются.
.\.venv\Scripts\python.exe download_models.py --component diarization
# Обработка выданных файлов: локально, без загрузки моделей из сети.
.\.venv\Scripts\python.exe scripts\test_hackathon_data.py
```

Тест использует MP3 и DOCX из корневого `data/`. Каждый запуск создаёт новый каталог `.local/data-smoke/run-*/` с `report.json`, WAV и интервалами говорящих. В отчёте только метаданные, количества, проверки и время, без содержания совещаний. SHA-256 до и после подтверждают, что исходные файлы не изменились.

Проверяется реальное декодирование в mono 16 кГц и запуск **исходных** моделей диаризации с проверкой интервалов. DOCX читаются, сохраняются в отдельные копии и повторно открываются; текст абзацев и ячеек сравнивается локально. Эта проверка DOCX не оценивает точность извлечения поручений или визуальную вёрстку экспорта приложения.

Результат локального запуска 23.09.2026 на CPU, автоматическое число говорящих:

| Запись | Длительность | Декодирование | Диаризация | Голосов / интервалов |
|---|---:|---:|---:|---:|
| Совещание №1.mp3 | 274,250 с | 0,510 с | 77,863 с | 6 / 36 |
| Совещание №2.mp3 | 206,031 с | 0,191 с | 54,345 с | 7 / 39 |

Все интервалы упорядочены и находятся в пределах записей. Число голосов — оценка модели, не подтверждённое число участников. Пик рабочего набора процесса обработки — 421 MiB по Windows `PeakWorkingSet64`; память Streamlit и других процессов сюда не входит. Оба DOCX прошли сравнение текстов абзацев и ячеек после повторного сохранения. Все четыре исходных SHA-256 сохранились. Это один замер на данной машине, не гарантия скорости.

Общий результат `PARTIAL` ожидаем: этот тест не запускает ASR/LLM и не оценивает WER/DER или полноту поручений. Если веса отсутствуют, этап помечается `BLOCKED`; если подготовлены — `READY_NOT_RUN`. `FAIL` и код выхода 1 означают ошибку проверяемых этапов; `PARTIAL` возвращает код 0, но не подтверждает готовность всего конвейера.

На этой Windows-машине исходные веса ASR пока недоступны: URL из манифеста вернул HTTP 401. Нужны доступ к тому же репозиторию модели или исходные `asr/model.pt` и `asr/tokens.lst` с совпадающими SHA-256. Сам `models.lock.json` и `vocab.json` весами не являются. Исходный MLX-модуль поручений здесь также недоступен; замена моделей не выполнялась.

Выданные организаторами файлы находятся в корневом `data/`. Локальные результаты тестов и веса в коммит не включаются.

## Приватность и ограничения

- Сервер слушает только `127.0.0.1`. Телеметрия Streamlit и Hugging Face отключена.
- Процессы обработки используют локальные пути, offline-флаги; Python-сетевые обращения блокируются audit-hook. FFmpeg ограничен локальными протоколами. Для промышленного закрытого контура дополнительно нужна изоляция сети на уровне ОС/инфраструктуры.
- Данные и журналы сохраняются в `.local/`. У каталога ограничены права; встроенного шифрования и многопользовательского контроля доступа нет. Кнопка удаления удаляет данные, связанные с текущей сессией. Исходный загруженный файл вне приложения не изменяется.
- Голосовая метка не является идентификацией личности. Имена подтверждает пользователь. Автоматическое число голосов может быть завышено; можно задать известное число говорящих.
- Плохое аудио, пересечения голосов, имена и смена языка повышают вероятность ошибок.
- Сроки вида «на следующей неделе» и «за месяц» сохраняются для уточнения. Дата и год не берутся из текущего времени.
- Проверка source_ids подтверждает существование реплик, но не доказывает правильность смыслового вывода модели. Результат проверяет секретарь.
- PDF, live-поток, боты Teams/Zoom/Meet, уведомления, СЭД, Docker/Linux и промышленное развёртывание пока не реализованы.
